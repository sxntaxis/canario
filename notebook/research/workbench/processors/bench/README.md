# Civic Processor Bench

State: **CLOSURE PASS — freeze-ready for the generic boundary; backend implementation remains unauthorized.**

This directory is the mandatory evidence gate between the processor SOTA research package and any
production `WORKBENCH-001` freeze/implementation. It is deliberately outside `actakit/`: benchmark
adapters are not production processors.

## Principle

The bench answers two different questions with two kinds of civic material:

1. **Controlled civic derivatives** provide stable ground truth. The first fixture is page 2 of the
   official TSE Puntarenas alcaldías PDF already preserved in the repository. Clean-scan, low-DPI and
   skew/noise variants are generated from that page so the textual truth is known independently of OCR.
2. **Natural civic artifacts** expose real-world surprises. Esparza shadow-custody PDFs/HTML/DOCX and
   later other municipalities must be run without changing the benchmark contract to fit them.

Neither class alone is sufficient.

## What this bench may do

- invoke candidate tools in a disposable benchmark environment;
- render/generate controlled variants under `work/`;
- record exact backend/model/version/config identity;
- measure text fidelity, false insertions, table fidelity, latency/resource signals and egress;
- invoke explicitly authorized cloud candidates using host-provided secrets;
- write non-secret result artifacts under this research directory.

## What it may not do

- create `actakit/processors` or freeze production processor interfaces;
- modify `0001` or semantic schema;
- store API keys/tokens in Git, SQLite, results, logs or ProcessRun material;
- treat Tesseract/Docling/VLM self-confidence as a universal comparable probability;
 - claim that every civic format is solved or that one backend is universally best.

`work/` is disposable and ignored. Results may be committed when their environment and corpus identity
are fully recorded.

## Metrics are evidence, not policy

The current runner records normalized CER/WER, token precision/recall, required-span recall, exact table
row recovery, elapsed time, process-tree peak RSS and Tesseract word-confidence statistics. These
measurements inform typed evidence and policy; they do not create a universal confidence score.

## Cloud/Codex bench rule

The official Codex CLI authenticated through a ChatGPT subscription is the reference
subscription-backed agent executor. The CLI owns ChatGPT authentication; ActaKit
and the bench do not inspect auth files or persist credentials. Only public or
explicitly approved egress is allowed under source policy, and results record
non-secret executor/model/request identity, bytes/pages sent, latency and the
applicable data-control profile.

Provider APIs remain optional deployment venues with their own secret, cost,
retention and egress controls. OpenAI-compatible endpoints remain capability-gated
transport escape hatches, not assumed feature parity. No universal backend/model
winner is frozen, and provider invocation remains separate from scoring.

## Gate outcome

The natural increment includes exact Esparza PDF/DOCX, FECOMUDI and Quepos actas,
an official spreadsheet, independent truth for two natural hard pages, and bounded
public Codex diagnostics. D2 page-level evidence and process-tree RSS are recorded.
Docling is explicitly optional, not default, because its disposable footprint was
material and no quality advantage was measured. `WORKBENCH-001` may freeze the
generic Processor/QualityEvidence/escalation boundary and reference profile; it
must not freeze a universal backend winner or authorize `actakit/processors`.
